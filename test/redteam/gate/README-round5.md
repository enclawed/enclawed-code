## 3. Attacks resisted (round 5)
- **Normalization**: an exhaustive scan of all 1.1M code points found none whose NFC, NFD, NFKC or NFKD form contains a control, tag, bidi or zero-width character. Visible look-alikes cannot become hidden characters through normalization or a normalizing tokenizer. The only normalization effect is the NFKC look-alike spoof listed under E1.
- **Malformed and overlong UTF-8** (overlong ESC `C0 9B`, `E0 80 9B`, CESU-8 surrogate tag chars, a truncated 4-byte tag prefix, 5-byte `F8`, overlong NUL): Node's decoder turns each one into U+FFFD, so no hidden escape or tag survives. The latin1 decoding path renders consistently with a C1-aware terminal.
- **The fixed-point loop is not reachable by combining or grapheme tricks**: nested surrogates (to depth 12), notice nesting, and CR/BS chains all converge within the cap. Only the nested-escape construction in E3 exceeds it.
- **Quoting that works**: a zero-width character inside "Enclawed", a soft hyphen inside it, an RLO/PDF around the tag, uppercase hex nonces, backticked *tagged* imitations, and Markdown links carrying a tag are all quoted. The backtick and `[Enclawed](url)` / `[Enclawed]:` exemptions only let *untagged* text through, which the model is told not to trust. That leaves a low residual risk only.
- **Nonce on disk**: the session file is a secret path and is denied to both `Read` and Bash `cat`. The nonce's real exposure is the model's own context, as described under E1.

## Priority for release
- **E2** should be fixed before release. It puts attacker wording inside Enclawed's trusted approval text, and the fix is small: escape interpolated values.
- E1, E3 and E5 are medium or low-medium and are all about which text the model or the approver trusts. Delivering notices out of band would close E1 and E5 together.
- E4 is a data-integrity false positive.
- The action gate's decisions themselves (allow, ask, deny) were not bypassed in this round.
